Your PDF fake passed. Did the invoice still contain the total?

Test the PDF your Laravel app actually emits: extracted text, page count and rendered visual snapshots. A fake proves you requested a PDF. These assertions inspect the bytes that came back.

Laravel test responses, file paths, raw bytes, Spatie Laravel PDF and Dompdf objects. No browser, no hosted service.

The test, and what it says when the total goes missing

Three Pest expectations against the response of a real invoice route. When the template drops the total, two of them fail and tell you exactly what the PDF contained.

tests/Feature/InvoicePdfTest.php

it('has one page', function () {
    expect($this->get('/invoices/1001/pdf'))
        ->toHavePdfPageCount(1);
});

it('shows the total', function () {
    expect($this->get('/invoices/1001/pdf'))
        ->toHavePdfText('Invoice 1001')
        ->toHavePdfText('120.00');
});

it('matches the approved layout', function () {
    expect($this->get('/invoices/1001/pdf'))
        ->toMatchPdfSnapshot('invoice-1001');
});

Three checks on the real document

toHavePdfText()
A case-sensitive substring of the PDF's text layer. Not OCR, not a layout guarantee.
On failure Expected PDF to contain "120.00". Extracted text: …
toHavePdfPageCount()
Catches the unexpected page break, or the invoice that silently grew a blank second page.
On failure Expected PDF to have 1 page(s); found 2.
toMatchPdfSnapshot()
Renders each page and compares it with a baseline you created on purpose. One mask and a per-page pixel allowance are available.
On failure PDF snapshot page 1: 312 changed pixels (allowed 0). Diff: …/diff-1.png

PHPUnit users get the same three as static PdfAssertions methods.

Two commands

Install

Add it to an existing Laravel 12 app with Pest or PHPUnit. The second command installs the pinned renderer inside the package. Network is needed to install, not to assert.

$ composer require --dev 'craigsimps/laravel-pdf-testing:^0.1' -W
$ vendor/bin/pdf-testing install

No registration step for Pest. The toolkit does not install a PDF generator; bring your own. Full details in the README.

You need

  • PHP 8.3 or 8.4
  • Laravel 12 (optional; plain PHPUnit projects work too)
  • Pest 3 or 4, or PHPUnit 11.5 / 12
  • Node 24.21.0 and npm 11, used only by the renderer
  • No browser, no Poppler, no Ghostscript, no hosted service

Offline after install. Assertions use in-memory PDF data, bundled fonts and a local Node process. No network requests, no telemetry.

Snapshots are explicit

A missing baseline fails. Nothing is created or overwritten unless you ask.

  1. 01

    Create the baseline on purpose.

    PDF_TESTING_UPDATE_SNAPSHOTS=1 vendor/bin/pest --filter='approved layout'
  2. 02

    Review the PNGs in tests/pdf-snapshots/invoice-1001/ before you accept them. On a mismatch, artifacts/diff-1.png shows the changed pixels in red.

  3. 03

    Commit manifest.json and page-*.png, ignore artifacts/, and never set the update flag in normal CI.

    Create and compare baselines on the same pinned renderer, operating system and architecture. Cross-OS pixel identity is not promised.

What it is not

Limits, stated next to the features and in the same type size.

  • Not OCR. Scanned PDFs without a text layer, and password-protected PDFs, are out of scope.
  • Not a replacement for fakes. Keep testing that your app requested a PDF. This tests what the PDF contains.
  • Not a service. Everything runs on your machine or CI. The toolkit collects no telemetry.
  • Not for untrusted uploads. It is for your own application and test PDFs, with a 60-second timeout per assertion.
